# USTAZ — платформа взаимного наставничества

Учебный full-stack MVP для IT-олимпиады: молодёжь Кыргызстана находит наставников,
бронирует консультации, выполняет миссии и получает баллы репутации, которые можно
обменять на бонусы партнёров.

Слоган: **«Делись знаниями. Расти вместе.»**

---

## Что уже работает (сквозной сценарий)

1. **Регистрация и вход** — ученик или наставник, JWT-аутентификация, пароли хранятся в виде scrypt-хеша.
2. **Каталог наставников** — 20 направлений (программирование, дизайн, маркетинг, подготовка к экзаменам, разговорный язык, музыка, фото/видео, робототехника и др.), поиск по имени/навыку/городу, фильтр по направлению и городу, сортировка; профиль наставника с рейтингом, отзывами, слотами и закреплённой формой записи.
3. **Расписание и бронирование** — наставник публикует слоты по одному или пачкой («каждый вторник в 18:00 на 4 недели»); ученик выбирает свободный слот и описывает тему → заявка в статусе `pending`.
4. **Подтверждение** — наставник подтверждает заявку → `confirmed`.
5. **Завершение** — обе стороны отмечают завершение сессии → `completed`, наставнику начисляется награда.
6. **Баллы** — баланс считается **только на сервере** из журнала `point_transactions`; начисления идемпотентны (повтор не удваивает баллы).
7. **Миссии** — присоединение, отправка отчёта, проверка администратором, начисление награды.
8. **Бонусы** — витрина акций со скидками и бейджами «Акция/Выгодно», фильтры по стоимости, блок «Как заработать баллы», атомарный обмен баллов на купон партнёра и раздел «Мои бонусы».
9. **Рефералы** — у каждого профиля есть код и ссылка `?ref=…`; после регистрации приглашённого пригласивший однократно получает **+50 баллов**, событие фиксируется в `referrals`, журнале баллов и уведомлениях.
10. **Достижения и уровни** — открываются автоматически по условиям (Новичок → Помощник → Наставник → Эксперт сообщества).
11. **Админка** — обзор метрик, модерация миссий, разбор спорных сессий, блокировка пользователей, журналы баллов/обменов/отзывов и аудит действий администраторов.
12. **Уведомления** — внутренние (in-app): колокольчик со счётчиком, группировка по датам, фильтр «Все / Непрочитанные», отметка «прочитано». События: новая заявка, подтверждение, отмена, завершение сессии, отзыв, зачёт/отклонение миссии, спор, бонус за приглашённого друга. Email и push не подключены.
13. **Интерфейс и мобильная версия** — на телефоне работает нижняя навигация (4 раздела + «Ещё» с полным меню), на десктопе — боковая панель; модальные окна открываются снизу, блокируют фон и закрываются по `Escape`; есть скелетоны загрузки, пустые состояния, тосты и понятные состояния ошибок.

Баллы **не являются деньгами или криптовалютой**, вывод средств не предусмотрен.

## Технологии

| Слой | Стек |
| --- | --- |
| Frontend | React 18, Vite, TypeScript, Tailwind CSS, React Router, Lucide |
| Backend | Node.js, Express, TypeScript, Zod |
| БД | SQLite через встроенный модуль `node:sqlite` (без нативной сборки) |
| Аутентификация | JWT (`jsonwebtoken`) + scrypt-хеш пароля (`node:crypto`) |

Архитектура готова к локализации: весь интерфейс на русском, тексты вынесены в компоненты и утилиты; для добавления `ky`/`en` достаточно вынести строки в словарь.

> **Требование к Node.js:** нужен Node.js **22.5+** (используется модуль `node:sqlite`).
> Проект проверен на Node.js v24. Демо-данные помечены знаком «Демо», фейковых партнёрств и цифр нет.

## Быстрый старт

Из корня проекта:

```bash
# 1. Установить зависимости backend и frontend
npm run install:all

# 2. Создать .env для backend
cp server/.env.example server/.env     # Windows PowerShell: Copy-Item server/.env.example server/.env

# 3. Создать базу и наполнить демо-данными
npm run seed

# 4. Запустить API и веб-приложение одновременно
npm run dev
```

Открыть **http://localhost:5173** — это dev-сервер Vite, проксирующий `/api` на backend (`http://localhost:4000`).

### Вариант «одним сервером» (production-режим)

```bash
npm run build      # собирает frontend и компилирует backend
npm run start      # backend отдаёт API и собранный frontend на http://localhost:4000
```

## База данных, миграции и seed

- **Файл БД:** `server/data/ustaz.db` (SQLite, создаётся автоматически).
- **Миграции:** SQL-файлы из `server/migrations` (`001_init.sql`, `002_notifications.sql`, `003_referrals.sql`) применяются автоматически при старте сервера (`migrate()` в `server/src/db.ts`).
- **Схема:** профили, слоты, бронирования, отзывы, журнал баллов (`point_transactions`), миссии и участники, бонусы и обмены, достижения, рефералы, аудит администраторов.
- **Идемпотентность начислений** обеспечивается частичными уникальными индексами:
  `ux_points_booking(booking_id, type)`, `ux_points_mission(mission_id, user_id, type)`, `ux_points_redemption(redemption_id)`.

Пересоздать базу с демо-данными:

```bash
npm run seed
```

## Экономика баллов

Все правила — в `server/src/config.ts`:

| Действие | Баллы |
| --- | --- |
| Подтверждённая сессия (наставнику) | +100 |
| Миссия (зависит от сложности) | +80 … +200 |
| Приглашённый друг зарегистрировался по ссылке | +50 |
| Бонус за серию занятий | +50 |
| Демо-бонус ученику (при seed) | +300 |

Уровни по **заработанным** (не потраченным) баллам: Новичок `0` → Помощник `200` → Наставник `600` → Эксперт сообщества `1500`.

## Сценарий демонстрации для жюри

1. **Лендинг** — открыть `http://localhost:5173`, показать суть платформы и объяснение экономики баллов.
2. **Вход ученика** — нажать «Заполнить» для аккаунта ученика → «Войти». Показать обзор: баланс, уровень, ближайшие сессии и карточку «До следующей награды».
3. **Бронирование** — «Наставники» → открыть профиль → выбрать слот → описать тему → «Отправить заявку». Заявка появляется в «Мои сессии».
4. **Подтверждение (роль наставника)** — выйти, войти как `aigerim@ustaz.kg` → «Мои сессии» → открыть заявку → «Подтвердить заявку».
5. **Завершение и баллы** — в той же сессии «Отметить завершение»; войти учеником и тоже отметить завершение → наставнику начислено **+100**; показать запись в разделе «Баллы и журнал».
6. **Миссии** — «Миссии» → «Присоединиться» → «Отправить результат». Затем войти администратором → «Админка → Миссии» → «Зачесть» → баллы ученику начислены.
7. **Бонусы** — учеником открыть «Бонусы» → «Обменять» → получить купон и увидеть его в «Мои бонусы». Рядом показать блок «Как заработать баллы».
8. **Рефералы** — войти как `aigerim@ustaz.kg` → «Бонусы» → блок «Пригласить друга»: показать ссылку `?ref=…`, двух приглашённых и начисленные **+100** баллов.
9. **Уведомления** — открыть колокольчик: группировка по датам, фильтр «Непрочитанные», отметка «Прочитать все».
10. **Админка** — показать обзор метрик, разбор спорной сессии, журналы баллов/обменов и журнал действий администраторов.

## Надёжность и обработка ошибок

- **Блокировка пользователя** атомарно отменяет его активные сессии (`pending`/`confirmed`), освобождает будущие слоты, убирает свободные слоты наставника из каталога и закрывает незавершённые заявки на миссии. Действие и его последствия пишутся в журнал аудита.
- **Истёкшая сессия** обрабатывается централизованно: любой авторизованный запрос с ответом `401` очищает токен и возвращает пользователя на экран входа вместо «сломанной» страницы.
- **Ошибка рендера** не оставляет белый экран: `ErrorBoundary` показывает понятное сообщение и кнопки «Перезагрузить» / «На главную». Технические детали видны только в dev-сборке.
- **Ошибки сервера** логируются одной строкой с временем, методом, путём, пользователем и стеком; клиенту отдаётся обезличенное «Внутренняя ошибка сервера». Ожидаемые конфликты (`UNIQUE`) логируются отдельно как `409` без стека.
- **Rate limiting**: 8 неудачных попыток входа на IP+email и 40 на IP за 10 минут, 10 попыток регистрации на IP+email и 30 на IP за час. Ответ `429` содержит `Retry-After`. Счётчики хранятся в памяти процесса и сбрасываются при перезапуске.
- **CORS по белому списку** `CLIENT_ORIGIN`: неизвестный источник не получает `Access-Control-Allow-Origin`, а в лог пишется предупреждение.

## Ограничения MVP

- Аутентификация по JWT в `localStorage`; refresh-токены и подтверждение email не реализованы.
- Rate limiting рассчитан на один процесс; при горизонтальном масштабировании нужен Redis.
- Аватары — инициалы с градиентом (без загрузки файлов и внешних URL).
- Партнёрские бонусы и отзывы — демонстрационные, помечены знаком «Демо».
- Вывод средств и любые «денежные» операции отсутствуют: баллы — только внутренняя репутация.
- Уведомления только внутренние: колокольчик опрашивает API каждые 45 секунд; email/push не подключены.
- SQLite подходит для демонстрации; для production потребуется внешняя СУБД и миграция данных.
